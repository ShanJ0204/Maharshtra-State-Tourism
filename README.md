# Beacon — AEO Discoverability Platform

Beacon is an **Answer Engine Optimization (AEO/GEO)** tool. Upload a CSV of the
prompts your customers actually ask, run them across the major LLM answer
engines, and measure whether **your brand is getting seen** — mentions,
position in the answer, citations of your domain, and share of voice vs.
competitors. It also generates prioritised AI recommendations to improve your
visibility.

> The repo previously hosted a static Maharashtra Tourism report. That file is
> preserved under [`legacy/`](./legacy/).

## Engines

| Engine | How it's queried | Citations |
|--------|------------------|-----------|
| **Claude** | Official `@anthropic-ai/sdk` with server-side web search (`claude-opus-4-8`) | ✅ from web search results |
| **ChatGPT** | OpenAI Chat Completions REST | — |
| **Gemini** | Google Generative Language API with Google Search grounding | ✅ from grounding chunks |
| **Perplexity** | Perplexity Chat Completions (OpenAI-compatible) | ✅ native |

Any engine **without an API key** falls back to a clearly-labelled **mock**
response, so the full UI and scoring pipeline work end-to-end before you add keys.

> **Google AI Overviews (AIO)** has no public API — it requires a paid SERP
> scraper (SerpApi/Serper). It isn't wired up yet; the four engines above cover
> the API-accessible answer engines.

## What it measures

- **Mention rate** — how often the brand appears across all (prompt × engine) queries
- **Position** — early / middle / late within the answer
- **Sentiment** — lightweight lexicon read around the mention
- **Citation rate** — whether your domain is cited as a source
- **Share of voice** — your mentions vs. tracked competitors
- **Trends over time** — run history stored in the browser (localStorage)
- **AEO recommendations** — generated by Claude from the run digest

## Product features

- **✨ Prompt generator** — describe your product and Claude writes realistic,
  unbranded discovery prompts (best-of, comparisons, alternatives, long-tail)
- **Visibility matrix** — prompt × engine heatmap: see at a glance which prompts
  you win, which you lose everywhere, and which engines are weakest
- **Most-cited sources** — the domains engines actually cite for your prompts,
  i.e. where AEO outreach (listings, reviews, guest content) will pay off
- **Live progress + cancel** — prompts run in batches with a progress bar and
  partial results streaming in; stop anytime
- **Engine status** — green/amber dots show which engines have live API keys
  vs. mock fallback
- **Filters & search** — filter results by engine, mentioned/missed/cited/errors,
  full-text search across prompts and answers
- **Exports** — per-run CSV (spreadsheet-ready), Markdown report, raw JSON
- **Run history** — last 8 full runs saved locally; reopen any past run, with
  ▲/▼ deltas vs. your previous run for the same brand
- **Saved setup** — brand, competitors, engines and prompts survive reloads
- **Hardened API** — concurrency-limited fan-out (8 parallel) with retry, so
  big CSVs don't trip provider rate limits

## Getting started

```bash
npm install
cp .env.example .env.local   # add the API keys you have (all optional)
npm run dev                  # http://localhost:3000
```

Without any keys, click **load sample** and **Run** to see the pipeline work
with mock answers.

### Environment variables

See [`.env.example`](./.env.example). All keys are optional — set the ones you
have. Keys stay server-side (used only in the Next.js API routes).

## Deploying to Vercel

This is a standard Next.js App Router app. Push the repo and import it in
Vercel, or use the Vercel MCP / CLI. Add the API keys as Vercel **Environment
Variables** (same names as `.env.example`).

## Architecture

```
app/
  page.tsx              Dashboard UI (client)
  api/run/route.ts      Runs prompts × engines, scores results
  api/recommend/route.ts  Claude-generated AEO recommendations
lib/
  engines/              One module per engine (+ mock fallback)
  analyze.ts            Mention / position / sentiment / SOV scoring
  csv.ts                Dependency-free CSV → prompts parser
  history.ts            localStorage run history
components/             Stat cards, share-of-voice, results table, recs
```

### Notes / next steps

- Run history is per-browser. To track trends across users/devices, swap
  `lib/history.ts` for Vercel Postgres or KV.
- Add Google AIO via SerpApi as a fifth engine in `lib/engines/`.
- The `/api/run` route caps at 50 prompts and runs all queries concurrently to
  stay within serverless time limits.
